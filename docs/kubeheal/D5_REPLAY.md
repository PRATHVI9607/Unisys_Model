# D-5 replay procedure

`python scripts/d5_replay_runner.py` is a one-shot k3d replay runner. Run it from the repository root after the updated Security Agent image is built and installed. It uses only the `k3d-kubeheal` context. `--timeout-s` is a total deadline with a reserved cleanup window; it must be at least 12 seconds.

The runner refuses to start unless the global `kubeheal-mode` ConfigMap is already `test` and the Security Agent DaemonSet currently has `FALCO_MODE=auto`. It checks the mode a second time immediately before enabling replay. It reads the single Running `prod` victim-app pod and rewrites the fixture namespace, pod name, pod UID, node, and container ID to that pod's current identity. It creates a full-UUID temporary ConfigMap with collision-safe `kubectl create` and temporarily patches a read-only replay mount plus `FALCO_MODE=replay`, `FALCO_REPLAY_PATH`, and `FALCO_REPLAY_NODE`. The node setting means only the Security Agent on the victim's node consumes the trace.

Success requires a matching `syscall_source=replay` Security event and a matching Fusion action with `dry_run=true`. Replay-origin events are forced to test mode inside Fusion and Executor even if the global mode changes during the run. Other Security Agent nodes fall back to their normal live Falco auto-detection while the target node consumes the replay. The runner prints both Redis records. It does not change `kubeheal-mode`. Its `finally` block restores the original Falco environment, removes the temporary mount and volume, waits for the DaemonSet rollout, and deletes the ConfigMap only after restoration is verified. If DaemonSet restoration fails, the ConfigMap is preserved so mounted pods remain healthy; the error includes the exact strategic patch and recovery commands. A timed-out create is cleaned up only when the ConfigMap carries this run's unique ownership label. Kubectl subprocesses and rollout status share the bounded total deadline.

The fixture `tests/fixtures/falco/ransomware_pv_encrypt_new_rules.jsonl` is hand-written. It is not a Falco capture and does not verify live Falco rules or live syscall collection. The process ID and event times are synthetic; only the target pod identity is read from the cluster. The event proves replay-to-Security-event-to-Fusion flow for this trace shape. Automatic decisions remain dry runs in test mode.

This runner was tested against a fake kubectl transport. It has not been deployed or executed against k3d yet.
