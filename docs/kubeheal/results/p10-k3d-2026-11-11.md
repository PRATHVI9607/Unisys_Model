Finding: in both events `field_attribution_json` is flat. In the first ten entries printed for the 0.1192 event the first
(`template.spec.initContainers[0].securityContext`) is 0.008695653639733791 and the other nine (`progressDeadlineSeconds`,
`revisionHistoryLimit`, `selector`, `selector.matchLabels`, ... `strategy.rollingUpdate`) are all 0.008695651777088642; the first
entries of the 0.2607 event show the same two values. A map this flat has no meaningful maximum, so `top_field` is not evidence
about the drifted CPU field. This is consistent with the Executor escalation `no_drift_at_field` for the 0.1192 event, and it
means the open attribution item is about the attribution values, not only about the mapping. Only the first ten entries of each
map were visible in the log excerpts; the rest were not checked.
